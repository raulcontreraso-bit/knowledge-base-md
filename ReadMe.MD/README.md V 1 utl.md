## 📌 File & Naming Conventions

To ensure cross-platform compatibility across Windows, macOS, Linux, and Git remote servers:

1. **Strict Lowercase:** Always use lowercase for directory names (`01_web_fundamentals`, `03_python`). Windows is case-insensitive, while Linux and Git are case-sensitive—mixing cases causes sync bugs and broken references.
    
2. **No Spaces (`snake_case` or `kebab-case`):** Spaces cause command-line script errors and ugly `%20` URL encodings. Use underscores (`_`) or hyphens (`-`).
    
3. **Numeric Prefixes (`01_`, `02_`):** Forces file systems and GitHub to display folders chronologically by study priority rather than strictly alphabetically.

## 💡 Naming Best Practices for GitHub Repositories

1. **Use `kebab-case` (Lowercase + Hyphens):**
    
    - ✅ `fullstack-systems-study-hub`
        
    - ❌ `DEV_VAULT` or `Dev Vault`
        
    - _Why:_ Hyphens and lowercase letters are URL-friendly, clean, and match standard GitHub conventions.
        
2. **Recommended Top Pick:**
    
    👉 `fullstack-systems-study-hub` or `cs-engineering-study-hub`
    
    _(Clear, professional, and explains exactly what the repo contains)._
