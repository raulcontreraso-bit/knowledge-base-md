## 1️⃣ Why the script failed as a `.bat` file

Looking at your screenshot, you saved the file as **`Create_Folders.ps1`**. That extension (`.ps1`) makes it a **PowerShell script**, not a batch script!

## 2️⃣ Why are we doing YAML? (`myst.yml` and `deploy.yml`)

YAML (`.yml`) stands for _"YAML Ain't Markup Language"_. It is the industry standard format for **configuration files**.

We are using **two** YAML files in this project, and each has a specific job:

### 1. `myst.yml` $\rightarrow$ The Blueprint of your Web Book

- **What it does:** It tells **Jupyter Book / MyST** how to build your website.
    
- **Why we need it:** Without `myst.yml`, Jupyter Book won't know the website title, author, or the order of pages in your left sidebar navigation menu (Table of Contents).
    

### 2. `deploy.yml` $\rightarrow$ The Robot Instructions for GitHub

- **What it does:** It sits in `.github/workflows/deploy.yml` and contains instructions for **GitHub Actions**.
    
- **Why we need it:** Every time you run `git push`, GitHub reads this file, turns on a cloud server in the background, installs Python and Jupyter Book, compiles your site, and publishes it live to GitHub Pages automatically.

**Spot on! Exactly.**

If this were _just_ a standard GitHub repository for storing code, you wouldn't need `myst.yml` or `deploy.yml` at all. You'd just push your `.py` or `.ipynb` files and call it a day.

Because you are building an **interactive web platform** (a published book/site), those two files act as your bridge from raw files to a live website:

**Yes, absolutely!** Using prefixes like `00_` combined with underscores (`_`) instead of spaces is a **widely adopted industry best practice**, especially when working with static site generators like Jupyter Book, static file servers, and version control tools like Git.

Here is why this structure saves you from head-aching errors down the line:

## 1. 🔢 Prefixes (`00_`, `01_`, `02_`) Preserve Ordering

Operating systems, file browsers, and site generators sort files **alphabetically** by default.

- **Without numbers:** A folder named `vanilla` comes after `pandas` and `numpy` (`numpy` → `pandas` → `vanilla`).
    
- **With numbers (`00_vanilla`):** It guarantees that foundational topics appear at the top of your sidebar navigation in Jupyter Book exactly in the logical order you intend to read or study them.
    

> 💡 **Tip:** Using double digits (`00_`, `01_`, `02_` ... `10_`) prevents "sort jumping" when you reach 10 or more folders (where `10` would otherwise sort before `2` alphabetically).

## 2. 🐍 Underscores (`_`) Avoid URL & CLI Path Escaping Issues

Spaces and special characters in file/folder names cause frequent bugs in build pipelines and web hosting:

- **Web URLs:** Spaces get converted to unsightly `%20` encodings in web links (e.g., `01_python/00%20vanilla/index.html`).
    
- **Terminal & Scripts:** Spaces require escaping or quotes (`cd "01 python/00 vanilla"`) in batch scripts (`.bat`), PowerShell, and Linux commands.
    
- **Import Statements:** In Python or JavaScript environments, module importers cannot parse directory names containing spaces or dashes cleanly.
    

## Summary Checklist for Clean Folder Structures

|**Format**|**Example**|**Best Practice?**|**Why?**|
|---|---|---|---|
|**Numeric Prefix + Underscore**|`00_vanilla`, `01_pandas`|**Yes**|Keeps logical order, clean URLs, terminal-friendly.|
|**Kebab-case (Hyphen)**|`00-vanilla`, `01-pandas`|**Yes**|Standard for web URLs, though underscores are preferred if importing python scripts.|
|**Spaces in Names**|`00 vanilla`, `01 pandas`|**No**|Causes `%20` in URLs and breaks command-line tools without strict quoting.|
|**Capital Letters**|`00_Vanilla`, `01_Pandas`|**No**|Windows is case-insensitive, but Linux (where GitHub Actions runs) **is** case-sensitive! Keep everything lowercase.|

However, in practice, relying on human care is risky because **Windows and Linux handle case sensitivity differently**, creating "silent bugs" that pass locally but break in GitHub Actions.

## ⚠️ The "Works on My Machine" Trap

Here is why casing issues sneak past even careful developers:

### 1. Windows File System (Case-Insensitive)

Windows remembers whether a folder is named `01_Python` or `01_python`, but it **treats them as identical**:

- On Windows, `cd 01_python` and `cd 01_Python` both work.
    
- If your `_toc.yml` has `01_python/index` but your folder is actually `01_Python`, **Jupyter Book on Windows builds without any error**.
    

### 2. GitHub Actions / Linux (Case-Sensitive)

GitHub Actions runs on **Ubuntu (Linux)**, where case sensitivity is strictly enforced:

- `01_Python` and `01_python` are treated as **two completely separate locations**.
    
- When GitHub Actions executes `jupyter-book build .`, it looks strictly for `01_python/index`. Because the actual directory on Linux is `01_Python`, Linux throws a **`FileNotFoundError`** and the build fails—even though it worked on your local Windows PC!
    

## 🛠️ The Git Renaming Gotcha

If you ever decide to fix a folder name from `01_Python` to `01_python`, Windows Git will often **ignore the change** because it doesn't see a case change as a new file/folder.

To force Git on Windows to recognize case changes, you have to run:

Bash

```
git config core.ignorecase false
```

...or rename it twice (e.g., `01_Python` $\rightarrow$ `temp_python` $\rightarrow$ `01_python`).

## 🎯 Best Practice Summary

|**Strategy**|**Risk Level**|**Outcome**|
|---|---|---|
|**All Lowercase (`01_python`)**|🟢 **Zero Risk**|Works identically on Windows, Mac, Linux, and GitHub Actions. You never have to think about it.|
|**Capitalized (`01_Python`)**|🟡 **Medium Risk**|Safe _if_ every reference in `_toc.yml` and markdown links matches the exact casing down to the letter.|

If you prefer using capitals (like `01_Python`), it will work fine as long as `_toc.yml` matches it **100% character-for-character**. But sticking to **strictly lowercase** is the industry standard because it removes the possibility of human error entirely!
